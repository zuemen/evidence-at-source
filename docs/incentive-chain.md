# 誘因鏈：為什麼每一方都會參與

一個靠簽章運作的系統，只有在**每一方各自都有理由簽**的時候才會被採用。這份文件說明證據前置的誘因結構——不是道德呼籲，是各方利益。

## 拱心石：反簽是互相保證

整條誘因鏈的支點是一句話：**每一方之所以願意簽，是因為對方的簽章保護了自己。**

- 簽發方（雇主／仲介／工廠／銀行）簽，是因為一份雙方共同封存的紀錄，讓它日後不會被單方指控「你當初給的數字是假的」——簽章對它也是保護。
- 勞工反簽，是因為這張憑證從此**由他自持、可攜、可選擇性揭露**，成為他辦事的通行證，而不是雇主抽屜裡一份他看不到、改得動的檔案。

兩邊都簽，才有「事後任一方單獨修改都會被偵測」。這不是靠強制，是靠雙方各自的自利指向同一個動作。

## 逐方誘因

| 參與方 | 為什麼參與 | 得到什麼 | 對應機制 |
|---|---|---|---|
| **勞工** | 一份自持、可攜、可選擇性揭露的證據，換到金融近用，同時不必把明細交給任何人 | 開得了戶、防報復、離境後帳戶可連動失效 | 錢包自持、選擇性揭露、連動撤銷 |
| **簽發方** | 一份雙簽封存的紀錄使它免於事後被單方指控；簽章成本一次性、在事件當下 | 可證明的盡職、更低的爭議處理成本 | 雙簽配對、證據前置 |
| **銀行（Agent A 的委託方）** | 得到「仲介費是否在法定上限內」「護照是否本人持有」這類可驗證的布林值 | 降低開戶風險與人頭帳戶責任，且不必保管勞工明細 | L0 授權、選擇性揭露、防報復提問邊界 |
| **品牌（Agent B 的委託方）** | 得到密碼學背書、經得起檢視的合規訊號與證據完整性指數 | 在強制人權盡職調查立法下降低法遵與商譽風險 | 交叉驗證、完整性證明、證據完整性指數 |

## 勞工的自述：`purpose` 欄位

誘因鏈裡最容易被寫成「假設」而非「事實」的一環，是勞工的參與意願。系統把它變成一個明示的動作：勞工反簽 attestation 時可附一個自述的 `purpose`（例：「為在台開戶之身份與意願查驗而反簽」）。

這個欄位由**勞工本人**簽發、不含任何第三方主張、不參與雙簽配對計算。它讓「下限由勞工給」不只是一句話——勞工的每一次反簽都是一個自己說明理由的行為，而不是被預設同意。實作見 [`packages/shared/src/attestation.ts`](../packages/shared/src/attestation.ts) 的 `AttestationInput.purpose`。

## 誘因會不會失衡

會，而且失衡處正是系統要防的地方：

- 若雇主的誘因是**少報工時**，交叉驗證（銀行入帳 vs 申報工時）與完整性證明（Merkle 承諾）使少報與不記錄都留痕。
- 若品牌的 Agent 的誘因是**多問一點以鎖定申訴者**，防報復提問邊界與差分攻擊偵測使個體無法被回推。
- 若機構授權的 Agent **越權查詢**，L0 授權層在讀到任何勞工資料之前就擋下。

誘因鏈不假設各方都善意；它假設各方都自利，並讓自利在架構上只能導向留痕、可驗證、不傷害勞工的行為。
