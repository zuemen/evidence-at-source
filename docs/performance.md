# 效能：這些保證的代價

**這份文件回答的問題**：隱私保護不是免費的，每一項保證都用簽章、鏈驗證、或一個零知識證明換來。「銀行真的跑得動嗎」這個問題只能用量到的數字回答，不能用形容詞。

全部數字由 [`scripts/benchmark.ts`](../scripts/benchmark.ts) 產生，**跑 `npm run bench` 可重現**。量測對象是與線上站、與測試完全相同的程式路徑，不是為了好看另外寫的一份。

## 量測條件

- 機器：12th Gen Intel Core i9-12900H，20 執行緒，16 GB RAM
- Node v25.8.0，win32
- 取**中位數**而非平均：一次 GC 停頓不應該變成簡報上的數字
- Poseidon 的首次建構（約 2 秒）在計時開始前先付掉，因此下列數字都是穩態成本
- 量測日期：2026-08-06

**先講浮動**：同一台機器連跑兩次，數字相差可達 **±30%**（產證明 511→669 ms、驗證 34→71 ms），
因為這是一台有其他負載的開發筆電，不是隔離的量測環境。下表取其中一次的完整輸出，
**沒有挑好看的那次、也沒有修飾**。這些數字要看的是量級——「毫秒級」「半秒級」「一秒級」——
而不是個位數的精確值。

## 三個判讀

### 一、最慢的一步是 vLEI 鏈驗證，而且是刻意的

一次完整查驗約 **1.3 秒**，其中絕大部分花在重走 GLEIF → QVI → 法人 → ECR 這條鏈。程式碼裡**沒有任何快取**：每一次查詢都從根重驗一遍。

這不是還沒優化，是取捨。**有快取，撤銷就有延遲**；GLEIF 撤銷 QVI 之後，快取沒過期的驗證方會繼續接受一條已經死掉的鏈。demo 裡「撤銷當場級聯」之所以能當場，就是因為沒有人在快取。

要更快也有明確做法——快取鏈驗證結果，再以 TEL 訂閱撤銷事件來主動失效——**那是工程優化，不是架構改動**。但在能證明撤銷即時生效之前，我們不打算先把它做掉。

以絕對值看，1.3 秒發生在一次開戶查驗或一次稽核查詢上，不在使用者每次點擊上；**這是可以接受的量級，不是需要辯解的量級**。

### 二、零知識證明的成本不是瓶頸，下載才是

產證明 669 ms、驗證 71 ms——對一次稽核來說可以忽略。真正的成本是 **2.6 MB 的電路產出物**（wasm ＋ 證明金鑰）必須先到使用者的裝置上。

所以線上站把它做成**點擊時才載入**：不看這一段的訪客一個位元組都不會下載。Demo Day 的風險也在這裡而不在計算——會場網路慢的話，慢的是下載，不是證明。備援做法見 [`demo-video-script.md`](demo-video-script.md)。

### 三、頻寬不是問題，手機跑得動

憑證 1.0 KB、一次出示 0.8 KB、證明本體 0.7 KB。**勞工端每次互動的資料量都在 1 KB 上下**，在移工實際使用的網路條件下沒有障礙——這對一個宣稱要給移工用的系統來說，是必須先確認的事。

## 沒有量的東西

誠實列出來，因為沒量到的數字不能拿來主張：

- **行動裝置上的產證明時間未量測**。上表的 669 ms 是筆電 Node 環境；手機瀏覽器會明顯更慢，實際數字要等在真機上量過才能寫。
- **母體只有六人**。k-匿名與省略偵測在數百人母體上的成本未量測。
- **並發未量測**。上表全部是單一請求的延遲，不是每秒可服務多少次查驗。
- **證明是單筆的**。一次稽核要對整條產線每個人各產一份證明的話，成本是線性疊加的，批次證明（recursion／aggregation）沒有做。
