# 防重放：為什麼不照抄 GLEIF 的 single-use nonce

**這份文件回答的問題**：GLEIF 的 mandate 憑證上有一個 `nonce: "single-use:92817"`，我們為什麼沒有照做。

實作在 [`packages/agents/src/replay.ts`](../packages/agents/src/replay.ts)。

## 照抄框架不等於用對框架

GLEIF 的 mandate 授權的是**一次執行**：支付這張發票，一次。憑證與動作的生命週期相同，所以把 nonce 放在憑證上完全正確——用掉就作廢，剛好。

我們的 `DelegationCredential` 授權的是**一段期間的提問權**：二十四小時內，針對某個範圍發問。這兩者的形狀不一樣。

把 single-use nonce 放在我們的憑證上，會變成**每問一個問題就要換一張授權**：機構重新簽發、勞工重新被要求審視一份新的授權——只因為品牌想再數一次某個群體。保護是真的，系統也真的沒法用了，而不能用的安全機制是另一種不安全。

## 所以 nonce 移到真正只發生一次的東西上

**查詢**才是一次性的動作。每個查詢請求帶一個 `jti`，閘門記住已經回答過的，重複出現就拒絕，回 `QUERY_REPLAY_DETECTED`。

| | GLEIF mandate | 本專案 DelegationCredential |
|---|---|---|
| 授權的是 | 一次執行 | 一段期間的提問權 |
| 憑證與動作生命週期 | 相同 | **不同** |
| nonce 的正確位置 | 憑證 | **查詢** |

授權維持為期間性的授予，被攔截的請求重放仍然失敗。**兩個目標都達成，代價是要多想一層。**

## 保留期限與查詢額度同一個週期

記住的 `jti` 有保留期限，與查詢額度的週期一致（目前 24 小時，定義在 [`policyVersion.ts`](../packages/shared/src/policyVersion.ts)）。

兩個方向都不能取巧：

- **永久記住**是一條緩慢的洩漏——而且會累積成一份「這個 Agent 問過幾次」的長期紀錄，那不是這個機制該產生的東西。
- **短於授權效期**會留下一個空窗：授權還有效，但被錄下的請求已經可以重放了。

過期的 id 是**被刪掉**，不是留著不看——與 `applicationMonitor` 同一條規則：沒有留下的資料，日後不會被用另一套說詞要走。

## 這個機制記住什麼

只有 id 被看過。**不記錄查了什麼，不記錄查的是誰。**

## 這一項擋不住什麼

**同一個 Agent 換一個 `jti` 重問一次，是允許的。** 這是設計，不是漏洞——持續查驗本來就要能重複發問。防重放擋的是**原封不動重放一個被錄下的請求**，不是「問兩次類似的問題」。後者由查詢額度與差分守門處理，那是另外兩層。
