# 解法對比矩陣（C10）

這張表回答評審必問的「你憑什麼、跟別人差在哪」。比較的是**類別**（competitor category）在五個關鍵屬性上的一般情形，不是對個別產品內部實作的斷言——個別產品應逐案查證（見 [`research/outline.yaml`](research/outline.yaml) C1–C9）。

五個屬性即本專案的五根支柱：

- **勞工自持**：關於勞工的證據由勞工本人持有、可攜，而非平台／雇主單方保管。
- **雙簽反簽**：勞工用自己的私鑰反簽雇主的紀錄，事後任一方單獨修改都留痕。
- **選擇性揭露**：驗證方拿到的是布林／匯總結論，不是原始欄位。
- **防個體查詢**：架構上拒絕回推到特定勞工（防報復）。
- **事件當下封存**：證據在事件發生的當下簽章，而非事後調閱／重製。

| 類別 | 勞工自持 | 雙簽反簽 | 選擇性揭露 | 防個體查詢 | 事件當下封存 |
|---|:---:|:---:|:---:|:---:|:---:|
| **本專案 Evidence at Source** | ✅ | ✅ | ✅ | ✅ | ✅ |
| 勞工申訴／發聲平台（Ulula、Issara 等） | ✗ 平台持有 | ✗ | ✗ | 部分（意圖有，非密碼學） | ✗ 事後回報 |
| 供應鏈盡職調查平台（Sedex、Diginex、EiQ 等） | ✗ 供應商上傳 | ✗ | ✗ | ✗ | ✗ |
| 區塊鏈供應鏈溯源 | ✗ 仍由供應商入鏈 | ✗ | 多半 ✗ | ✗ | 部分（上鏈時間戳） |
| SSI／VC 身分錢包（EUDI 等） | ✅ | ✗ 無雇主紀錄反簽 | ✅ | ✗ 無提問層 | ✗ 非特定事件 |
| eKYC 身分驗證（Onfido、Jumio 等） | ✗ | ✗ | ✗ | ✗ | ✗ |
| 移工金融產品／匯款 | ✗ | ✗ | ✗ | ✗ | ✗ |

## 一句話定位

- 相對**勞工申訴平台**：它們讓勞工「發聲」，但證據仍由平台持有、無密碼學反簽；本專案讓勞工「持有並封存證據」。
- 相對**盡職調查／區塊鏈溯源**：它們把供應商提供的資料數位化或上鏈，但**資料來源仍是供應商單方**；本專案的資料由勞工反簽，工廠無法單方造假或省略（交叉驗證 + 完整性證明）。
- 相對**SSI 錢包**：本專案站在 SSI 之上，但多了三件通用錢包沒有的東西——**雇主紀錄的勞工反簽、防報復的提問層、以及交叉驗證/省略偵測**。
- 相對**eKYC**：eKYC 驗「你是誰」；本專案驗「關於你的事實是否可信」——不同層，可互補。

**唯一同時具備五根支柱的，是本專案。** 這不是因為別人做得差，而是因為它們解的是相鄰但不同的問題——沒有一個把「證據由勞工持有 + 雙方共同封存 + 只回答不交付 + 防個體回推」這四件事放在同一個系統裡。

> 誠實註記：上表為類別層級的分析定位。個別產品可能在某格優於其類別的一般情形；若要在正式材料引用，應對該產品逐案查證。
