# 勞工自述工時：證據等級與誠實邊界

## 它補的是哪一個洞

這個系統原本對**最強的對手**偵測率是零。

那個對手不是竄改紀錄的工廠，而是：**控制打卡系統、照著自己申報的數字付薪、並脅迫勞工簽名的工廠**。它從一開始就不說謊——它只是不記錄。

| 既有機制 | 對這個對手 |
|---|---|
| 雙簽配對 | 沒有篡改。那筆紀錄從一開始就是這個數字 |
| 交叉驗證（工時 vs 銀行入帳） | 少報就少付，帳完全平 |
| 完整性證明（Merkle 承諾） | 從沒發過那筆紀錄，承諾涵蓋的與勞工手上的**同時為空**，比對不出異常 |
| 勞工確認率 | **脅迫產生 100% 覆蓋率，比誠實工廠好看** |

四個機制的共同前提是：**雇主先寫下了某樣東西**。證據的產生權完全在雇主手上，所以「不產生」這個動作本身就繞過了全部。

`SelfReportedHoursCredential` 改變的是這一件事：**勞工不需要任何人同意，就能把一件事記上檔。**

## 五種狀態

有了自述憑證，雇主申報與勞工紀錄的關係可以被分成五種：

| 雇主憑證 | 勞工自述 | 狀態 | 意義 |
|---|---|---|---|
| 有（已反簽） | 無 | `NORMAL` | 一般情形 |
| 有（已反簽） | 有，數字相符 | `CONFIRMED` | 本系統能產生的最強狀態 |
| 有（已反簽） | 有，數字不符 | `DISPUTED` | **爭議**（新訊號） |
| **無** | **有** | `OMITTED` | **雇主未產生任何紀錄**（新訊號） |
| 無 | 無 | `NO_INFORMATION` | 無資訊——**明確不等於合規** |

第四列是這整個機制的理由。在此之前，「雇主根本不記錄」不是一個系統看得見的事件。

實作見 [`packages/agents/src/selfReport.ts`](../packages/agents/src/selfReport.ts)，五種狀態各有測試。

## 證據等級：刻意排在最低

`issuerTier` 新增 `SELF_REPORTED`，位於 `SELF_DECLARED` **之下**：

```
SELF_REPORTED  <  SELF_DECLARED  <  THIRD_PARTY_VERIFIED  <  AUTHORITY_CERTIFIED
   勞工自述          工廠自簽            稽核機構背書              主管機關認證
```

這不是謙虛，是準確。自述憑證是**單方聲明，可被偽造**——勞工可以寫任何數字。把它排在工廠自簽之下，意味著任何要求 `minimumIssuerTier: 'SELF_DECLARED'` 以上的驗證方**根本收不到它**；要用它的人必須指名要。

## 誠實邊界：它的價值是統計的，不是單筆的

**「那勞工亂報怎麼辦？」** 這是第一個會被問的問題，而誠實的答案是：**單一勞工的自述不是證據，也不該被當成證據。**

它的價值在分歧的**統計形狀**：

- 一整廠的自述工時**系統性地**高於雇主申報 → 這是一個訊號
- 少數幾筆分歧 → 可能是誤記、記錯期間、或個別造假，不構成結論
- 一位勞工說自己加班 300 小時 → 這在本系統裡不會、也不應該讓那家工廠被判定違規

所以兩個查詢都是**匿名匯總且需通過 k-匿名**：`getSelfReportDivergenceRate` 回比率、`getUnmatchedSelfReportCount` 回筆數，**都不回傳是誰**。這一點格外重要——在所有訊號裡，「這位勞工的說法和工廠不一致」是最危險的一句話，被指認為那個人正是本系統存在的理由所要防止的報復。

## 仍然沒有解決的

**自述可以被脅迫。** 一個能強迫勞工簽名的工廠，同樣能強迫勞工自述一個好看的數字。這張憑證讓「不記錄」變得可偵測，但它**不是**對脅迫的解方——脅迫訊號是另一個機制的工作。

**自述可以被壓制。** 勞工要有能力、有網路、且不怕，才會自述。一個環境足夠封閉的工廠可以讓自述率為零，而**零自述與零問題在數據上看起來一樣**。這是這個機制最根本的限制，它無法從系統內部解決。

**這一切仍是推導出來的。** 這個設計來自對文件的分析，不是來自任何一位移工告訴我們他們會不會用、敢不敢用、在什麼情況下會用。在那之前，「勞工會自述」是一個假設，不是一個已知。
