代價

合規失敗不是罰款，是股價事件

巨大機械涉強迫勞動——國際品牌取消合作、ESG 評級下降、出口產品遭到扣押。

而時鐘已經在倒數：臺美對等貿易協定（ART）承諾 3 年內全面禁止向製造業與漁撈業移工收取招募費；勞動部 2026/04 已公告防制強迫勞動，公平招募列入移工評鑑標準。

資料來源：美家人力《RBA 供應鏈合規的可驗證憑證機制》，2026/08/22 產業工作坊

現況

企業現在能做的，只有兩件事——兩件都不夠

「企業現在能做的就是『慎選仲介 ＋ 後續移工訪談』，
但缺乏主動性及 100% 保證合規。」

—— 命題方原句。不是我們的推測。

  • 慎選仲介：無法 100% 約束　·　訪談移工：可能有串證之虞
  • 而且仲介合規 ≠ 每個案件都合規——同一家仲介，RBA 客戶與非 RBA 客戶不同案。

工時表可以事後重製，仲介費收據可以不放進資料夾。
稽核員看到的，永遠是工廠願意給的那一批。

根因

問題不在稽核強度，在證據結構

關於勞工的四項事實——仲介費、證件保管、契約同意、工時——
全部由單方出示。勞工本人在自己的證據鏈裡沒有位置。

  • 只要出示權在一方手上，資料就永遠可以被篩選。
  • 只要勞工沒有簽章，紀錄就永遠可以被事後重寫。

同一個結構，同時造成 Track 05 的開戶困境與 Track 06 的稽核失真。

解法

我們不新增任何義務

勞基法第 30 條早就要求逐日記載工時至分鐘、保存五年
（違反罰 9 萬–45 萬）。

我們做的是讓既有義務變成可驗證。

  • 事實發生的當下，簽發方 ＋ 勞工各簽一次，當場封存。
  • 查驗時勞工選擇性揭露，對方只拿到布林值或匯總值。
  • 實際工時、金額、薪資？payload 裡那個 key 密碼學上不存在——不是遮蔽、不是 null。

六信任點 · 逐點命中

PrincipalAgent 掛 GLEIF vLEI 鏈上的 ECR 角色憑證，不是設定檔裡的公鑰名單——連機構的可信層級也由 QVI 寫在鏈上
Authorization機構給上限（查詢型別／範圍／期限）× 勞工給下限（看過範圍才出示）＋ nonce 重放保護
Tool / Action能力不存在：approveAccount／transferFunds… grep 不到，不是被 if 擋掉
Policy GateL0 授權 → L1 憑證 → L2 提問；L0 失敗＝勞工資料零讀取
Audit Log雜湊鏈＋ES256 封緘，挑戰方可獨立重驗；再加外部檢查點，連尾端截斷都被反證
Expiry / Revocation六路撤銷即時生效且完全不快取——有快取就有撤銷延遲

機構信任層 · GLEIF vLEI

信任是一條憑證鏈，不是一份名單

GLEIF Root (2-of-3 多簽) → QVI → 法人 vLEI → ECR 給 Agent ／ OOR 給拍板的人

  • 上游任何一張被撤銷，下游立即全部失效——沒有名單要同步。
  • KERI／ACDC：Blake3 SAID、pre-rotation KEL、TEL 錨定——偷到舊金鑰也偽造不了撤銷紀錄。
  • npm run demo:vlei：17 步主張，exit 0 即全數成立。

誠實標註：demo 的信任根是自建沙盒，非真 GLEIF。但 SAID 與參考沙盒逐位元組一致——驗的是結構，台灣 QVI 成立即可換根。

AI 的位置

AI 被關在正確的位置

"An LLM confidence score cannot override failed cryptography,
authority, identity or mandate checks."

—— GLEIF《Trustworthy AI agents》, 2026/08

  • 判斷路徑上沒有語言模型，而且有測試釘死：六個決策套件不得出現任何 model import。
  • 模型只被允許把已經作成的判定寫成人話；產出的每一句都要通過規則比對，矛盾就丟棄改用確定性樣板。
  • 這也是 prompt injection 演示的真正對象：注入能改變模型寫的字，改變不了送到人眼前的判定。

誠實邊界

敢說做不到什麼，其餘的話才有重量

可獨立驗證

  • 竄改 → 配對不成立
  • 隱藏欄位 → key 密碼學上不存在
  • 能力邊界 → grep 得到就破功
  • 稽核軌跡 → 挑戰方可重驗
  • 尾端截斷 → 外部檢查點反證

做不到 / 不宣稱

  • 偵測脅迫——刀架在脖子上，指紋一樣按得下去
  • 簽發當下就合謀造假（雙簽只防事後改寫）
  • 入帳 ≠ 勞工實際拿到
  • 信任根仍是沙盒；未接任何真實系統

比賽規範原句：「評審要看的不是宣稱系統可信，而是流程中哪個環節有可驗證的設計。」

誰付錢

我們解的是「開戶之後」——命題方自己要的那一塊

「我們不只解決了『開戶』，更幫助移工累積了合法的『信用歷史』。」

—— 美家人力《移工數位信任》第 13 頁

品牌已經在付稽核費——要的是持續可驗證，以及被 NGO 質疑時能出示的驗簽收據
仲介雙簽讓誠實的簽發方免於事後被單方指控；T1/T2/T3 分級讓好仲介與自我聲明分得開
銀行四項事實一次出示、只拿布林；離境即撤銷級聯——開戶之後才有東西可以評估

MGPay 用 PCODE 2566 解開戶（通路與 KYC），我們證明關於這個人的事實——那些不在他們手上，在雇主與工廠手上。互補，不是競爭。

我們還沒驗證的：單位經濟的兩個假設——每次稽核工廠端文件準備約 15 人天、導入後可降至三分之一——目前標註為 [假設]寫在 docs/adoption-path.md，尚未經任何真實利害關係人證實。這是我們今天最想問各位的問題。

可信度

不要相信我們說的任何一句話

  • 585 個測試，GitHub Actions 每次 push 全跑，CI 綠。
  • node poc/dual-signature.mjs → 篡改後配對 false　·　node poc/selective-disclosure.mjs → totalHours present? false
  • npm run verify:external → 9/9 vectors passed——這支 verifier 不依賴我們任何一行程式碼。

別人不用我們的實作，也能驗我們的憑證。
這才是「可驗證」的最終形式。

全部合成資料；私鑰在瀏覽器產生、從未離開裝置；靜態站無後端。
