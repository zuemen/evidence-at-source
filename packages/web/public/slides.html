Evidence at Source
證據前置

事實在發生當下雙簽封存——
AI Agent 只能問到答案，拿不到資料。

Live demo：zuemen.github.io/evidence-at-source

問題

兩個場景，同一個根因

  • 80 萬移工：近三成曾受詐、估逾 17 億；離境後帳戶沒人知道，成為現成人頭帳戶。
  • RBA 供應鏈稽核：稽核員永遠只看到工廠願意給的那一批紙本。

出示權在雇主手上——勞工在自己的證據鏈裡沒有位置。

解法

勞工自持雙簽憑證錢包 ＋ 兩個機構 Agent

  • 每件事實（仲介費、證件、契約、工時）發生當下由簽發方＋勞工雙簽封存，事後改不了。
  • 銀行 Agent 拿到布林結論＋建議（人類覆核）；品牌 Agent 拿到合規率。
  • 實際工時、金額、薪資？payload 裡那個 key 密碼學上不存在——不是遮蔽。

六信任點 · 逐點命中

PrincipalAgent 屬於 GLEIF vLEI 法人鏈上的機構（LEI），持 ECR 授權角色憑證——「代表誰」可驗證
Authorization機構給上限（查詢型別／範圍／目的／最低簽發層級）×勞工給下限（看過範圍才出示）
Tool / Action能力不存在：approveAccount／transferFunds… grep 不到，不是被 if 擋掉
Policy GateL0 授權 → L1 憑證 → L2 提問；L0 失敗＝勞工資料零讀取
Audit Log每次決策記層級／准駁／原因碼／授權依據（授權雜湊＋ECR SAID）＋可驗簽收據
Expiry / Revocation授權 24h 到期；四路撤銷即時生效，含 GLEIF 撤 QVI 全鏈級聯

Policy Gate

三層閘門：先驗人、再驗料、最後驗問題

  • L0 授權層——這個 Agent 憑什麼問？（授權憑證＋vLEI 鏈，每次重驗）
  • L1 憑證層——這份證據成立嗎？（雙簽配對／撤銷／簽發層級／產線綁定）
  • L2 提問層——這個問題能問嗎？（拒個體查詢／k-匿名／差分攻擊偵測）

順序顛倒的話，未授權的 Agent 會在被拒之前就讀到勞工資料——順序即保證，測試可證。

機構信任層

vLEI：信任是一條憑證鏈，不是一份名單

GLEIF Root (2-of-3 多簽) → QVI → 法人 vLEI (LEI) → Agent ECR

  • 上游任何一張被撤銷，下游立即全部失效——沒有名單要同步。
  • TEL 事件錨定 KEL：偷到舊金鑰也偽造不了撤銷紀錄。
  • 出示打成單一 JSON 可攜出示包：驗證方只釘 root，離線重驗整條鏈。

攻防

所有隊伍 demo 快樂路徑——我們 demo 自己被攻擊

  • Prompt injection 無效：判斷路徑上沒有 LLM，注入的指令只是資料。
  • 差分攻擊被擋：兩次查詢相減可回推個人 → 第三次查詢被拒＋審計序號。
  • 竄改被攔：改一個欄位，SAID 斷鏈；雇主事後重簽，勞工反簽雜湊不符。

稽核與撤銷

可以被質疑，也可以自證

  • 稽核軌跡：每次決策的層級／准駁／授權依據，稽核台即時可看。
  • 查驗收據：被 NGO 質疑時，出示可獨立驗簽的「何時驗了哪些項目」。
  • 撤銷反向通知：憑證被撤，日誌反向索引通知所有曾驗證者。
  • 離境連動：勞工離境＝全部憑證失效，人頭帳戶的窗口直接關上。
